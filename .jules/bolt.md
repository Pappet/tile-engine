## 2024-06-09 - Short-Circuiting Dynamic Conditions with Stateless Checks
**Learning:** In hot simulation loops (like `periodic_reaction_system`), executing expensive dynamic condition evaluations (`evaluate`) before cheap stateless checks (like `mix_hash` probability rolls) wastes significant CPU time, especially since evaluating conditions requires chunk memory reads and iteration. Additionally, utility functions like `mix_hash` used across crate boundaries in hot loops must be explicitly marked `#[inline]` to allow the compiler to perform cross-crate inlining and avoid severe function call overhead.
**Action:** Always place cheap, stateless checks (like probability rolls or static bounds checks) before expensive memory-dependent evaluations in hot loops to short-circuit execution. Always ensure that small, frequently called utility functions used across crates are marked with `#[inline]`.
